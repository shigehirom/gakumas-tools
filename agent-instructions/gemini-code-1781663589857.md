# Antigravity Agent Instruction: MongoDB 'memories' Collection Schema Expansion for Out-Game DSL Ver 1.2

## 1. 目的（Objective）
本指示書は、既存の MongoDB 内に存在する `memories` コレクションのデータ構造を拡張し、「学園アイドルマスター out-game DSL 仕様書 Ver 1.2」に準拠したアビリティ効果（DSL文字列）および初期インベントリ（スキルカードID群）を保持・運用可能にすることを目的とする。

本タスクを実行するにあたり、既存のドキュメント構造に対する後方互換性（非破壊的拡張）を完全に維持し、移行および検証用のスクリプトを安全にビルドせよ。

---

## 2. 拡張対象のコレクションおよび新規スキーマ定義

### 対象コレクション
- データベース: `gakumas_db` （または現在の環境で稼働中の対象DB）
- コレクション名: `memories`

### 拡張後のドキュメント・モデリング（JSON/BSON構造）
既存のドキュメント構造に、`produce_abilities`（アビリティ配列）と `initial_inventory`（初期インベントリ情報）の2つのフィールドを新規追加する。

    {
      "_id": ObjectId("..."),
      "user_id": "string",
      "memory_id": "string",
      "acquired_at": ISODate("..."),
      "p_idol_id": integer,
      "scenario": "string", // "初星コミュ" | "N.I.A" | "H.I.F" などの識別子
      "total_assessment": "string",
      
      // ===== 新規追加フィールド 1: プロデュースアビリティ配列 =====
      "produce_abilities": [
        {
          "slot_index": integer, // 0から始まるスロットインデックス
          "raw_text": "string",  // ゲーム内から抽出したオリジナルの日本語テキスト
          "dsl": "string"        // out-game DSL Ver 1.2 準拠のパース済み文字列
        }
      ],
      
      // ===== 新規追加フィールド 2: 初期持ち込みインベントリキャッシュ =====
      "initial_inventory": {
        "skill_card_ids": [integer], // 初期配布 + アビリティで確定したスキルカードIDの配列
        "p_item_ids": [integer]      // 初期配布PアイテムIDの配列（無ければ空配列）
      }
    }

## 3. 実装要件（Requirements）

### 要件1: 既存ドキュメントへのマイグレーションスクリプトの作成
既存の `memories` ドキュメントに対して、デフォルト値を持つ新規フィールドを一括挿入（または既存テキストからのコンバート）を行うPythonスクリプト（`migrate_memories_v1_2.py`）を作成せよ。
- 既存レコードに `produce_abilities` が存在しない場合は空配列 `[]` で初期化すること。
- `initial_inventory` が存在しない場合は、`{"skill_card_ids": [], "p_item_ids": []}` で安全に初期化すること。

### 要件2: パース処理における Ver 1.2 DSL 規則の厳守
アビリティテキストを `dsl` フィールドに変換・格納するロジック（パーサー）を実装、あるいは既存のパーサーを拡張する際、以下の仕様を完全に満たすこと。
1. **複数IDのカンマ区切り解決:**
   「アッチェレランド（ID: 402, 403）」のように、無印とプラス版を同時にプレイフックとする場合、メタ文字 `|` は使用せず、必ず `id=(402,403)` のようにカンマ区切りでパースして格納すること。
2. **HIF編特殊効果の抽象化:**
   「カード除外移動」は `card_exclude(id=23)`、「カード使用数追加」は `extra_card_play+1` のように仕様書に定義された関数・パラメータ名へ厳密にマッピングすること。
3. **リセットカウンターの考慮:**
   `@card_play` や `@exam_start` などのインゲーム（試験中）に割り込むトリガーに対して `limit=n` 修飾子が付与されている場合、out-game進行エンジン側が「試験開始フェーズでカウンターを0リセットする」ためのトリガー識別を妨げない構造にすること。

## 4. エージェントへの実行指示（Step-by-Step Action Tasks）

- **Step 1:** `memories` コレクションの現在のインデックスおよび数件のサンプルドキュメントを確認し、既存のスキーマ構造をパースせよ。
- **Step 2:** 上記「2」で定義した拡張スキーマを適用するための Mongoose スキーマ、あるいは Python (PyMongo) 用のバリデーションモデル（Pydantic等）の定義コードを作成せよ。
- **Step 3:** 既存データに対して非破壊的にデフォルト値を流し込む、または既存の `raw_text` に基づいて `dsl` を自動生成して `produce_abilities` を埋めるマイグレーションスクリプトを記述・実行せよ。
- **Step 4:** 移行後、特定の `memory_id` を指定して `produce_abilities[].dsl` の文字列、および `initial_inventory.skill_card_ids` が正しくクエリ・取得できることを検証するテストコード（Assertion）を実行し、成否をログに出力せよ。
