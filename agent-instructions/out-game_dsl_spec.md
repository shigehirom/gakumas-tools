# 学園アイドルマスター out-game DSL 仕様書 (Ver 1.3)

## 思考プロセス
本仕様書は、サポートカードの効果定義のみに留まっていた Ver 1.0 の out-game DSL を拡張し、各種プロデュースメモリー（初星コミュ編、NIA編、HIF編）が持つアビリティ効果を同一のパーサーで安全かつ非破壊的に処理できるよう再設計したものである。
1. **トリガーのインゲーム拡張：** 従来のスケジュール終了マスに依存するトリガーに加え、試験開始（`@exam_start`）や特定のスキルカード使用時（`@card_play`）といったインゲーム（レッスン・試験中）のイベントフックを共通の引数（`type`, `id`）構文で内包する。
2. **効果対象とアクションの分離：** 恒常的なパラメータバフの他に、初期バフ付与（`focus`, `positive`, `genki`）、カード使用数追加（`extra_card_play`）、インベントリ（山札・捨札・除外）の操作アクション（`card_exclude`）を抽象化して定義する。
3. **複数ID解決の標準化：** スキルカードの「無印 / ＋版」の同時指定など、複数のIDを対象とする場合は `id=(402,403)` のようにカンマ区切りで列挙し、プログラム側での配列化（`split(',')`）を容易にする。
4. **仕様の共通化による恩恵：** サポートカード（凸による数値変動あり・`values` 配列保持）と、プロデュースメモリー（固定値・配列なし）が完全に同じ文法ルール上で動くため、Python側の進行管理エンジンは単一のパースルーチンを使い回すことが可能となる。
5. **パラメータボーナスの対応（Ver 1.3）：** メモリーの持つ各種パラメータボーナス（小数点以下の値）に対応し、`@passive` トリガーでの記述仕様を明確化。

---

## 1. 概要
本DSL（Domain Specific Language）は、プロデュースセッションにおける「out-game（スケジュール進行・育成・インベントリ管理）」および「in-gameの開始・特定行動への割り込み」に伴うステータス変動やイベントフックを、Pythonベースの進行管理エンジン側で安全かつ正確にパース・トラッキングするために設計された共通仕様である。

## 2. 構文定義（グラマー）
基本文法は以下の規則（BNFライク）に従う。

    <dsl_string> ::= "@" <trigger> [ "inner_attributes" ] ":" <spaces> <effect> [ "modifiers" ]

    <trigger>    ::= "init" | "passive" | "lesson_start" | "lesson_end" | "exam_start" | "card_play" | ...
    <attributes> ::= <key> "=" <value> [ "," <attributes> ]
    <effect>     ::= <target> [ <operator> <value_token> ] | <action>
    <operator>   ::= "+" | "-" | "="
    <value_token>::= <number> | <decimal> | "{v}"
    <modifiers>  ::= <key> "=" <value> [ "," <modifiers> ]

### 限界突破（サポカ）と固定値（メモリー）のデータ構造
- **サポートカード：** 特訓段階による数値変動を吸収するため、効果数値を `{v}` とし、マスタ（JSON）側の `values` 配列（長さ5）から現在凸に応じた数値を動的にバインドする。
- **プロデュースメモリー：** 数値の段階変動がないため、`{v}` は使用せず直接数値を DSL 内に記述する。

## 3. トークンリファレンス

| `@passive` | `@passive` | 常時発動（各種レッスンボーナス、パラメータバフ、確率上昇等） |
| `@lesson_start` | `@lesson_start(type=dance)` | 通常/SPレッスン開始時（属性引数: `vocal`, `dance`, `visual`） |

| `@exam_start` | `@exam_start(type=final)` | 試験・オーディション開始時（種別引数: `mid`＝1次/中間, `final`＝最終） |

| `@event` | `@event` | サポートイベント発生時（デフォルトのフック） |

### 3.2. 対象パラメータ・識別子
- `vo` / `da` / `vi` : ボーカル / ダンス / ビジュアル（基本ステータス）
- `hp_max` / `hp` : 最大体力 / 現在体力
- `coin` : Pポイント
- 各種バフ（サポカ・メモリーのパラメータボーナス用）：
  - `vo_bonus` / `da_bonus` / `vi_bonus` : ボーカル / ダンス / ビジュアルボーナス
  - `vo_lesson_bonus` / `da_lesson_bonus` / `vi_lesson_bonus` : 各レッスンボーナス
  - `vo_sp_lesson_rate` / `da_sp_lesson_rate` / `vi_sp_lesson_rate` : 各SPレッスン発生率
  - `lesson_support_rate` : レッスンサポート発生率
  - `event_param_bonus` / `event_heal_bonus` : イベントパラメータUP / イベント回復量UP
- インゲーム初期バフ（メモリー用）：
  - `focus` : 集中（主にセンスで使用）
  - `positive` : 好印象（主にロジックで使用）
  - `genki` : 元気
- インゲーム特殊効果（HIF編用）：
  - `extra_card_play` : スキルカード使用数追加（ターン内制限の追加）
- インベントリ・ID指定：
  - `card_id` / `pitem_id` : 獲得する対象のID指定（例: `card_id=1`）

### 3.3. 演算子
- `+` / `-` : 数値の加算・減算処理（例: `vo+65`, `hp-15`, `vo_bonus+1.5`）
  - ※発生率やボーナス値など、パーセンテージや倍率を表す場合は小数の指定（例: `1.5`）をサポートする。
- `=` : IDや特定の状態を直接指定・代入する処理（例: `card_id=420`）

### 3.4. アクション（関数型効果）
- `card_exclude(id=[カードID])` : **【HIF編拡張】** 山札または捨札にある指定IDのカードを、ランダムに1枚除外領域へと移動させる。

### 3.5. 修飾子（オプション・末尾のカッコ内）
- `(limit=[X])` : 最大発動回数制限。
  - ※トリガーが `@card_play` などのインゲーム系である場合、**「試験ごとに（各試験の開始時に）カウンターがリセットされる」** という仕様として処理する。
- `(prob=[X])` : 確率発動判定（1〜100の整数）。

## 4. 複数ID指定に関するシンタックスルール
特定のスキルカードの「無印版」と「＋版」の双方をトリガーや効果対象として指定する場合、正規表現のメタ文字（`|`）は使用せず、**カンマ区切りによる列挙**を行う。

- **文法：** `id=(ID_1,ID_2)`
- **記述例（アッチェレランドとアッチェレランド+）：** `@card_play(id=(402,403)): ...`
- **実装ガイダンス：** パーサーは正規表現でカッコ内の文字列（`402,403`）をキャプチャした後、各言語の `split(',')` メソッド等を用いて速やかに数値配列（`[402, 403]`）へと変換し、`if current_card_id in id_list:` の判定ロジックに流し込むこと。

## 5. 実際のDSL変換・データ表現例

### ユースケース1：サポカ（初期パラメータ加算・凸変動あり）
- 元テキスト：`[初期] 初期ボーカル上昇+65`
- DSL表現：`@init: vo+{v}`
- マスタ数値：`"values": [52, 55, 59, 62, 65]`

### ユースケース2：HIF編メモリー（カードプレイ割り込み・除外移動）
- 元テキスト：`試験ごとに、以降 1 回まで、プライド（ID: 420, 421）使用後、ランダムな山札か捨札の 眠気（ID: 23）を除外に移動`
- DSL表現：`@card_play(id=(420,421)): card_exclude(id=23)(limit=1)`

### ユースケース3：HIF編メモリー（カードプレイ割り込み・使用数追加）
- 元テキスト：`試験ごとに、以降 2 回まで、アッチェレランド（ID: 402, 403）使用後、スキルカード使用数追加+1`
- DSL表現：`@card_play(id=(402,403)): extra_card_play+1(limit=2)`

### ユースケース4：初星コミュ編メモリー（レッスン開始時・確率発動）
- 元テキスト：`ダンスSPレッスン開始後、55%の確率で元気+4`
- DSL表現：`@lesson_start(type=dance): genki+4(prob=55)`

### ユースケース5：NIA編メモリー（試験開始時・自動判別仕様）
- 元テキスト：`【センス専用】最終オーディション開始時、90%の確率で集中+1`
- DSL表現：`@exam_start(type=final): focus+1(prob=90)`
- ※【センス専用】のテキスト文言は、効果対象が `focus`（集中）であることからプログラム側でセンス用バフと自明に判定できるため、DSLの条件式からは省略する。

### ユースケース6：メモリー（常時発動のパラメータボーナス）
- 元テキスト：`ボーカルレッスンボーナス+1.5%`
- DSL表現：`@passive: vo_lesson_bonus+1.5`
- ※表示上は `%` を伴うが、DSLのパース値としては純粋な数値を記述し、トリガーは `@passive` とする。

## 6. 実装エンジニア向けパース＆実行注記
1. **デリミタ基準の分割処理**
   トリガー引数（`id=(402,403)`）と効果修飾子（`(limit=2)`）のように、文字列内に複数のカッコが連続して出現するため、必ずコロン（`:`）をデリミタとして前後に分割してから独立して正規表現マッチングを行うこと。
2. **試験ごとの制限カウンターリセット**
   修飾子 `limit=n` を持つ効果が、`@init` や `@passive` などのout-game全体に及ぶものか、あるいは `@card_play` などのインゲーム（試験中）に及ぶものかをトリガーから判定し、インゲーム効果である場合は、スケジュールマスが「試験・オーディション」に突入するたびに、発動回数カウント（`current_limit`）を `0` にリセットする処理を実装すること。

## 7. MongoDB 'memories' コレクション拡張スキーマ
DSLの拡張に伴い、プロデュースメモリーが持つアビリティ効果や初期インベントリ情報をDB（`memories` コレクション）で保持・運用するためのスキーマ定義である。

### 拡張後のドキュメント・モデリング（JSON/BSON構造）
既存のドキュメント構造に対して、`produce_abilities`（アビリティ配列）と `initial_inventory`（初期インベントリ情報）の2つのフィールドを定義する。

```javascript
{
  "_id": ObjectId("..."),
  "userId": "string",
  "name": "string", // メモリー名（例: "24/12/31＿13881"）
  "pIdolId": 1, // integer
  "params": [763, 2000, 1103, 34], // [vo, da, vi, hp] 等
  "pItemIds": [48, 73, 78, 0], // 所持Pアイテム
  "skillCardIds": [223, 250, 68, 131, 175, 180], // 所持スキルカード
  "customizations": [{}, {}, {}, {"56": 1}, {}, {}],
  
  // ===== 以下、本仕様に伴う新規追加・拡張フィールド =====
  "scenario": "string", // "hajime" | "nia" | "hif"
  "difficulty": "string", // "regular" | "pro" | "master" | "legend" | "selection" | "main"
  "event": "", // イベントメモリー等のフラグ用（デフォルト: ""）
  
  // プロデュースメモリー固有の付加情報
  "produce": {
    // 獲得可能スキルカード情報
    "skillCard": {
      "id": 123, // in-game の skill-cards ID
      "name": "string", // スキルカード名（検証・表示用）
      "timing": "start", // 獲得タイミング: "start" (開始時に獲得) | "middle" (中間試験/1次オーディション後に獲得)
      "customization": { "56": 1 } // in-game カスタマイズ情報（未強化時は {} など）
    },
    // out-game DSL アビリティ配列
    "abilities": [
      {
        "slotIndex": 0, // 0から始まるスロットインデックス
        "rawText": "string",  // ゲーム内から抽出したオリジナルの日本語テキスト
        "dsl": "string"       // out-game DSL 準拠のパース済み文字列
      }
    ]
  }
}
```
