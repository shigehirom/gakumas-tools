# 学園アイドルマスター ツール開発 エージェント引き継ぎ資料

## はじめに：新しいエージェントへ
このドキュメントは、Mac miniのローカル環境からTrueNAS上のネットワークボリュームへ移行した「学園アイドルマスター（Gakumas）ツール」のワークスペースにおいて、これまでの開発コンテキストや運用ルールを新しいAIエージェント（あなた）に引き継ぐためのものです。
あなたは今後、このワークスペース上でユーザー（shigehiro）とペアプログラミングを行い、ツールの開発・運用をサポートします。

## 1. プロジェクトの概要と環境
- **対象リポジトリ**: 
  - `gakumas-tools` (https://github.com/shigehirom/gakumas-tools) - 本家のフォーク。CLI機能の追加やシミュレーションエンジンの改修がメイン。
  - `gakumas-support_cards` - サポートカード等のデータ管理
  - `gk-img` - 画像アセット管理（本家へのPR用）
- **動作環境**: 
  - **新環境**: TrueNAS上の共有ボリューム（例: `/Volumes/gakumas-workspace/` などとしてマウント）。
  - **クロスプラットフォーム運用**: Mac mini、Windows 11 (ROG Ally X)、TrueNASコンテナ等から共通のワークスペースとしてアクセスされます。
- **連携サービス (MCP)**:
  - **Ollama (Gemma 4)**: ローカルLLMとして適宜処理を委譲・活用してください。
  - **MongoDB**: キャッシュ（`simulation_results`）やロードアウト（`loadouts`）の保存先。IPは `192.168.100.4` を参照します。

## 2. これまでの主な作業内容とコンテキスト
直近では以下のような作業を行ってきました。
1. **コンテスト新シーズン（直近はシーズン47）への対応**: 新シーズンのステージデータやカードデータの追加、シミュレーションの検証。
2. **編成Markdownの展開作業**: 「XX_あじふらい.md」などの共通スキルカードリストを、指定されたPアイドルごとに個別展開・上書きする定型作業。（※ Knowledge Item「あじふらい氏のコンテスト編成Markdownの展開手順」を参照）
3. **ワークスペースのTrueNAS移行**: Mac miniのローカルストレージからTrueNASへのディレクトリ構造の移行と動作確認。

## 3. 開発における重要ルール (AGENTS.md 準拠)
以下は絶対に遵守すべきルールです。

- **シミュレーション検証の徹底**: エンジン修正時やシーズン更新時は、キャッシュを回避して必ず「新規計算」を行い、スコアの妥当性（exit 0でもスコアが0でないか等）を確認すること。
- **TrueNASへのデプロイ制限**: `./deploy.sh` は対話的なパスワード入力が必要なため、エージェントは**絶対に自動実行してはいけません**。ユーザーに手動実行を促してください。
- **アップストリーム（本家）との同期**: `surisuririsu/gakumas-tools` と同期した後は、必ず `packages/gakumas-data` で JSONの再生成等ビルドコマンドを実行すること。
    - 古いスプレッドシートデータとの不整合（ブロックDSL構文エラー）が起きた場合は、Git (`origin/master`) のCSVデータをチェックアウトして復元する手順を踏むこと。
- **データ登録時の命名規則**: ユーザーによるメモリ登録時は、先頭に `YY/MM/DD＿` (全角アンダースコア) を付与すること。
- **画像アセットのPR**: 本家 `gk-img` へPRを出す際は、`.png` ではなく `.webp` 形式にし、サフィックス（`_crop`など）を外したIDのみのファイル名にすること。

## 4. 日常的なワークフロー
- **RAGデータの更新**: データ更新時は、ユーザーへの報告とともに `python3 generate_rag_docs.py` を実行し、NotebookLM/Gemini用のMarkdownドキュメントを最新化してください。
- **シミュレーション実行**: `contest`, `tournament`, `rehearsal` などのCLIコマンドを実行し、最適なメモリ構成を探索します。結果は随時 `--save` オプションでMongoDBに保存します。
