あなたはテクニカルライターとしての能力も兼ね備えたシニアシステムアーキテクトです。
これまでの開発・リファクタリングを経て確定した、サポートカードの効果を表現する「out-game（スケジュール進行・育成用）DSL」の仕様を、第三者の開発者が読んでも100%理解・実装できるレベルの「公式仕様ドキュメント（Markdown形式）」としてまとめ上げてください。

ドキュメントの構成や美しさは、`gakumas-tools/packages/gakumas-data/Effects.md` のin-game用DSL仕様書のスタイル（構文ルール、トークン表、具体的なコード例、データ構造の一貫性）を強く意識し、洗練されたものにしてください。

## 3. ドキュメントに必ず含めるべき構成要素

### ① イントロダクションと設計思想
- 本DSLが、in-gameのシミュレーション（Node.js環境）に入る前の「out-game（スケジュール・インベントリ・育成フェーズ）」におけるステータス変動やイベントフックを、プログラム（Python）側で安全かつ非破壊的にパース・トラッキングするために設計されたものであることを明記してください。

### ② 構文定義（グラマー）
基本文法（BNFライク、または視覚的に分かりやすい構造表現）を明記してください。
- 構文：`@トリガー[(属性)]: 対象[演算子]数値(修飾子)`
- 動的数値バインド：限界突破（特訓段階）による変動を吸収するため、数値部分に `{v}` を用いてマスタ側の `values` 配列と紐付ける設計思想の解説。

### ③ トークンリファレンス表（完全版）
以下の要素を、表（Table）を用いてきれいにマッピング・解説してください。
- **トリガー (`@` から開始):**
  - `@init` : プロデュース開始時（初期ステータス即値加算のみに制限）
  - `@passive` : 常時発動・確率アップ・倍率バフ系パッシブ
  - `@class_end` : 授業・営業終了時
  - `@rest_end` / `@rest_select` : お出かけ終了時 / 休む選択時
  - `@shop_select` / `@shop_buy_drink` : 相談選択時 / 相談でPドリンク交換後
  - `@gift_select` : 活動支給・差し入れ選択時
  - `@special_class_start` : 特別指導開始時
  - `@lesson_end(type=属性)` / `@sp_lesson_end(type=属性)` : 通常レッスン終了時 / SPレッスン終了時（属性には `vocal`, `dance`, `visual` が入る）
  - `@exam_end` : 試験・オーディション終了時
  - `@event` : サポートイベント枠（テキストに特定タイミングがない場合のデフォルト）
- **対象パラメータ:** `vo`, `da`, `vi`, `hp_max`, `hp`, `coin`, `[vo/da/vi]_bonus`（パラメータボーナス）, `[vo/da/vi]_lesson_bonus`（レッスンボーナス）
- **演算子:** `+` (加算), `-` (減算)
- **修飾子 (オプション):** `(limit=[X])`（回数制限）, `(prob=[X])`（確率発動）
