# 依頼：限界突破（特訓段階）に伴う効果値変動のデータモデリング実装および再変換

## 1. 目的
サポートカードの効果テキストに含まれる動的な数値変動（限界突破/特訓段階 0〜4凸に応じた値）を正確にシミュレートするため、`convert_json_to_dsl.py` を改修し、構造化された `values` 配列（長さ5）を持つ新しい `support_cards_master.json` を生成してください。

## 2. 思考プロセスの強制（重要）
実際のコード改修を始める前に、必ず `## 思考プロセス` というセクションを設けてください。
そこ行で、以下の仕様をどのようにPythonロジックへ落とし込むか、日本語でステップバイステップの計画を箇条書きで記述してください。
- 既存の固定テキスト（例: `vo+65`）を、変数プレースホルダー `{v}` を含んだDSL文字列（例: `@init: vo+{v}`）へどのように正規表現で置換するか。
- 中間データ（wikiスクレイピングデータ等）に存在する `uncap_0` 〜 `uncap_4` の値を、正確に `values` 配列へマッピングするバリデーション方法。

## 3. 改修後の期待するJSONデータ構造
各アビリティ効果（`unlocked_effects` 内のオブジェクト）の数値を `{v}` に置き換え、凸段階ごとの数値を `values` に分離します。
※out-gameシミュレーションに直接関係のない確率・サポート率アップ等は、数値を無理に配列化せずプレースホルダー文字列（例: `"@passive: support_rate_up"`) で処理するか、数値をそのまま残して安全にフォールバックさせてください。

## 4. スクリプト（`convert_json_to_dsl.py`）の修正要件
1. **トリガー判定・後処理ロジックの維持**:
   前回の改修で実装した `@passive` の分離、レッスン属性（`type=vocal` 等）の付与、サポートイベントの `@event` 統一ロジックはそのまま維持・継承してください。
2. **プレースホルダー置換エンジンの実装**:
   - `ability` テキスト内の具体的な数値部分（例: `+65` などの整数）を正規表現でキャプチャし、DSL文字列内では一律で `+{v}`（または単に `{v}`）に動的置換する処理を追加してください。
   - ソースデータ（中間データ）の辞書から `uncap_0`, `uncap_1`, `uncap_2`, `uncap_3`, `uncap_4` のプロパティをループで取得し、文字列（`"28%"`等）から数値のみを抽出（パーセント記号などを安全に除去）して `int` 型の配列として `values` フィールドに格納してください。

## 5. テスト駆動型実行の要求
スクリプトの最下部の `if __name__ == '__main__':` ブロック内に、`uncap_0`〜`4` のデータを含んだモック（ダミーカードデータ最小2枚分）をハードコードしたテストケースを用意し、正しくプレースホルダー化されたDSLと数値配列が組み合わさったJSONファイルがエラーなく出力されるか、スタンドアロンでの検証を実行してください。
